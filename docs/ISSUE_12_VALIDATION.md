# Issue #12：暂停后自动恢复播放

## 证据与范围

[issue #12](https://github.com/cyrahs/spoticonn/issues/12) 报告在 `59391b8` 的 Apple TV + HomePod 组合中，从 Spotify 暂停后会再次播放。尚无该次运行的完整时间线，因此不能断言本次用户现象已经由某一条源码路径解释，也不能声称实机每次都能复现。

该版本中存在可通过模拟引擎验证的路径：普通 `paused` 没有取消输出重连；暂停时 `Flush` 失败会安排重连；重连进入 `acquire` 后主动发送 `resume`。此外，建连持有生命周期锁，用户暂停事件可能在建连完成后才被处理。本次修复处理这些路径，不涉及 iOS 原生控制回传、封面或配对 UI。

## 修复后的约束

- 每个 Spotify 进程独立保存期望播放状态和操作代次，恢复任务同时绑定账号实例、播放器实例、进程代次、操作代次及目标。
- Spotify 暂停／停止事件到达回调时即使旧操作失效，不等待生命周期锁或恢复定时器。网页暂停也在等待生命周期锁前取消连接；等待后的命令再次核对账号身份。
- 用户暂停先取消恢复并隔离、排空 PCM，取消组合加入并清缓冲／待机。清缓冲或待机失败只关闭输出、报告错误，不安排恢复。网页操作无需等待 Spotify 事件才停止输出。
- 内部暂停在事件合并前仅消费一次暂停确认。确认后的临时暂停允许合法故障恢复；额外暂停使操作失效。内部暂停命令失败、确认超时或状态无法安全核对时不自动恢复。
- 连接完成及发送内部 `resume` 前重新检查当前请求。已取消的连接即使晚到返回成功也被关闭，不调用 `Begin` 或 `resume`。替换进程、换账号或换目标后的旧恢复不能控制新会话。
- 已有组合输出的 `CancelJoin`／`Flush` 负责取消并等待成员任务退出；暂停期间的迟到组状态不会恢复播放，断线回调也不会创建恢复任务。

### 固定引擎的暂停确认

go-librespot v0.9.0 的 [播放器命令处理](https://github.com/devgianlu/go-librespot/blob/v0.9.0/player/player.go) 在已有音频输出且 `Pause` 成功时为每次暂停命令发送 `EventTypePause`；[daemon 事件转换](https://github.com/devgianlu/go-librespot/blob/v0.9.0/daemon/controls.go) 将其转换为 WebSocket `paused`。没有输出时可能不产生该事件，因此确认等待有两秒上限，不能仅凭 HTTP 成功认定可自动恢复。

该协议没有暂停命令 ID 或用户来源标记。这里使用单个内部命令的确认额度、连续事件和实时状态核对，不按时间窗忽略全部暂停。WebSocket 丢失事件、内部暂停和外部暂停几乎同时发生时，无法从协议证明单个事件的来源；未确认情况保持暂停，并需在实机验收中重点记录这一边界。升级引擎时需重新验证每次暂停命令的事件行为。

## 自动回归

`internal/bridge/playback_intent_test.go` 记录并断言实际 `Player.Command` 序列，覆盖：

| 场景 | 断言 |
| --- | --- |
| Spotify 暂停／停止已到达，但恢复定时器先被处理 | 不重开输出、不再发送 `resume` |
| Spotify 和网页暂停，正常／Flush 失败／Standby 失败／之后断线 | 保持暂停且无自动恢复，PCM 不再送往输出 |
| 内部故障暂停及其迟到确认 | 合法重连继续；命令为原连接 `pause, volume, seek, resume`，故障 `pause`，重连 `volume, seek, resume` |
| 单设备／组合连接中从 Spotify 或网页暂停 | 取消连接上下文；模拟晚到成功也不启动输出、不发送 `resume` |
| 连接后的 seek 控制期间用户暂停 | 最终命令止于 `pause, volume, seek` |
| 组合成员加入中暂停，随后到达 joined／playing／disconnected 回调 | 取消加入，保持暂停，不恢复主输出 |
| 快速暂停后显式恢复 | 旧恢复请求失效，新请求可播放 |
| 换账号、替换进程、切目标后重新投递旧恢复及输出回调 | 不再向旧或新播放器发送控制命令 |
| 内部暂停未确认 | 清除确认额度，不吞掉下一次用户暂停，不自动恢复 |
| 诊断 | 包含事件、状态、恢复计划／取消和内部 resume 来源，不包含曲目 URI 或用户名 |

已有 `internal/airplay/group_test.go` 还验证了成员确认前、Open 中、Join 中及加入后的取消，并检查下一次播放不会创建重叠成员会话。

运行：

```sh
go test -race -count=1 -timeout=5m ./...
go vet ./...
```

本次使用模拟 Spotify／AirPlay 引擎；没有使用真实账号凭据或连接 Apple TV／HomePod。

## 部署后实机验收（待执行）

记录部署提交、设备组合、暂停入口、暂停与再次出声时间、复现次数和总尝试次数。每次试验保存暂停前后的管理状态及最近诊断，避免等待太久使有界诊断列表被覆盖。不要保存凭据、授权回调 URL 或原始子进程参数。

- [ ] 正常播放后从 Spotify App 暂停，等待至少 90 秒，确认保持无声、Spotify 和网页保持暂停。
- [ ] 在输出故障出现「恢复中」时暂停，等待超过下一次恢复时间，确认没有新的内部 `resume`。
- [ ] 从网页重复上述两步，确认不依赖 Spotify 事件延迟才停止输出。
- [ ] Apple TV 正在加入时暂停，确认 HomePod 停止、迟到加入不会重新出声。
- [ ] 输出故障后不操作暂停，确认内部暂停得到确认后能够正常恢复。
- [ ] 快速暂停／恢复、切目标、换账号后，确认只有最新请求可播放。
- [ ] 若仍自动恢复，将脱敏时间线与设备实际声音对应，继续定位；不得将本次模拟测试当作原用户现象已得到实机确认。
